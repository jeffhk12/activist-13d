How should we train the 13D network?

21 October 2026 | Teaching and proposed design review; no new fitting

Purpose: test whether a carefully trained network improves later 13D return predictions. The first fixed experiment is preserved. Lecture 4 supplies several complementary components and alternative choices. A bounded validation plan is preferable to trying every possible combination and selecting the best observed later result.

Source and distinction

Reviewed the latest download, lecture_4_neural_networks_deep_learning.pptx (114 slides). Slide numbers below refer to that file. Backpropagation computes gradients. An optimizer uses them to update weights. Batch size determines which examples contribute to each update. A loss defines what errors matter; regularization constrains fitting. These choices can interact, so one-factor comparisons help explain behavior and a small predeclared set of combinations can test interactions.

A concrete budget issue: epochs versus updates

For 365 training events, full-batch training makes one update per epoch. A mini-batch size of 32 gives 12 updates per epoch, including a final smaller batch. Thus 500 epochs mean 500 versus 6,000 updates. Each comparison must state whether it holds data passes, updates or computation fixed, report all three where possible, and specify the treatment of the last batch and the regularization term. More epochs are not automatically better later prediction.

What the existing diagnostics show

Across all 15 year/seed fits, the saved penalized training objective is lower at update 500 than at 400. Every fit has zero fully inactive training neurons at the final update. This supports inspecting optimization and stopping before blaming dead ReLUs or adding complexity. It does not prove convergence, establish a cause of poor prediction, rule out partially inactive units, or show that extra training would help validation performance. Proposed order of work

  1. Design the validation split. Identify which earlier observations have fully matured outcomes at every validation origin. Two-year labels and a small early panel may leave insufficient data for useful nested chronological validation; check feasibility rather than assume folds exist. The previously inspected 2021-2023 results remain development evidence.
  2. Inspect the existing learning curves. Plot training MSE, penalty, total objective, gradient norms and activation fractions for all years/seeds. Distinguish the optimized objective from later-event error; do not select a stopping point using those later outcomes.
  3. Define a small optimization comparison. Hold inputs, target, network and seeds constant. Specify bounded learning-rate/training-budget candidates for Adam; optionally add a mini-batch version and momentum SGD. Fix trial count and budget conventions before execution. No exact candidate grid has yet been approved or frozen.
  4. Assess regularization and stopping. Compare a bounded penalty range and, if validation is feasible, a specified early-stopping rule. A larger maximum budget plus validation stopping is a candidate, not an inference that 500 was too short.
  5. Test limited combinations and information changes separately. Interactions may justify a few declared combinations. Activation, loss, normalization, width/depth and richer features should each answer a stated question. Changing the loss may change the statistical quantity being predicted. Preserve a finite search budget and the original negative comparison.

What we already combined

Tabular MLP + hidden ReLU + He-style hidden-weight initialization + linear output + full-batch Adam + explicit L2 penalty + five-seed prediction average. These are compatible pieces of a complete procedure. Adam is not stacked with RMSProp as another optimizer, while L2 and early stopping can be combined if specified and validated.
